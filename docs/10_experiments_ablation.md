## 2. What each experiment established

| experiment | question | measured result | conclusion (and its limit) |
|---|---|---|---|
| **E01** remove ReferenceNet | does the appearance channel reach the decoder? | runtime −12%; the `strength=0` variant reproduces E01 numbers to 5 decimals | code path **verified** (bank=None ⇒ plain self-attention); identity quality needs trained weights |
| **E02** remove CLIP | is the semantic channel live? | runtime −33 %; `hist_corr_mean` 0.565 → 0.532 (largest colour change of any ablation) | cross-attention is ~1/3 of our runtime (5 stacks × 5 blocks); semantic fidelity still unmeasurable |
| **E03** remove Pose Guider | is motion conditioning live? | runtime −25 % (the guider forward is skipped); metrics unchanged | pose features are computed **once** per clip → a constant, not per-step, saving; pose accuracy needs trained weights |
| **E04** remove temporal attention | what does frame-mixing cost? | **runtime −39 %**, every quality metric **bit-identical to baseline** | by construction: motion modules are zero-initialised = identity at init, so this is a *cost* experiment; flicker needs training |
| **E05/E05b** weaken reference attention | is the knob honest? | `strength=0` ≡ E01 numbers; `0.5` sits in between | the interpolation is mathematically sound (`validate_build.py` proves 0.0 ≡ no-bank) |
| **E06/E06b** steps | cost vs quality | 2 steps −36 % and `temporal_delta` 0.177 (less frame-to-frame change); 16 steps +84 % | runtime ≈ linear in steps (0.90 / 1.40 / 2.59 s for 2 / 8 / 16) |
| **E07/E07b** guidance | CFG cost | total −3 %; **direct measurement: 77.4 ms/step with CFG vs 68.0 ms/step without (+14 %)** | CFG doubles the *math* but only +12–14 % wall-clock at this model size (per-layer overhead dominates); at production scale the gap approaches 2× |
| **E08** degraded pose | does pose quality propagate? | runtime −29 %, metrics unchanged | with random weights the pose branch cannot influence content; the run validates the *degradation harness* (blur/jitter/occlusion) a trained model would exercise |
| **E09/E09b** frames | cost vs sequence length | 4 frames −57 %, 16 frames +31 % | sub-linear in F at this scale (fixed overhead dominates); production clips are much longer, where temporal attention dominates |
| **E10/E10b** resolution | cost vs detail | 64² −50 %; 128² +10 % and the **only run whose peak RSS rises meaningfully (386 → 478 MB)** | memory-vs-resolution is visible; the "4× per doubling" attention rule needs production token counts |
| **E11** VAE fp16 | precision cost | **+1115 % runtime (1.40 s → 17.07 s)** | fp16 convolutions lack optimised CPU kernels: never use fp16 on CPU; on GPU it is the standard production choice |
| **E12** slower motion | do metrics track motion? | runtime −27 %, metrics unchanged | identical metrics for half-speed motion expose a limitation: with random weights the output does not depend on the pose, so *no* pose metric is informative |
| **E13** concat fusion | alternative pose fusion | params 1,981,643 → 1,950,511 (−31k) | concat makes the Pose Guider output 4-channel (saving params) and `conv_in` 8-channel; production uses addition |

## 3. Cross-cutting findings

1. **Zero-initialisation is an inference-time trap.** E04's identical metrics are
   the direct consequence of `zero_module(proj_out)` in the motion modules: at
   initialisation the temporal branch *is* the identity. Any ablation of a
   zero-initialised branch must be read as a cost experiment.
2. **Cost is dominated by branch count, not conditioning "strength".** Removing
   an entire attention family (temporal −39 %, CLIP −33 %) costs far more than
   weakening one (reference at 0.5: −8 %): the number of blocks, not a strength
   knob, determines the work.
3. **Ablation ≠ measurement when weights are random.** Five of the twelve
   required ablations produce *identical* metrics by construction (E03, E04,
   E08, E12, and effectively E01/E05b). What they validate is the harness — and
   each report row says so.
4. **Cheapest meaningful quality signal without training:** the VAE round-trip
   (`vae_psnr` ≈ 18.2 dB for the random tiny VAE; a real `sd-vae-ft-mse` round trip
   is typically > 25 dB). Anything below that on a trained run points at the VAE,
   not the diffusion model.
5. **Sanity properties that *are* provable without training** (and were):
   `strength=0` ≡ no reference bank; CFG-off halves the UNet batch; concat fusion
   changes only `conv_in`/`pose_guider` widths; zero-init output conv makes ε̂ ≡ 0.
